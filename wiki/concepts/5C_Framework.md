## 定義

5C Prompt Contract（5C 提示契約）是由 Ugur Ari 提出的極簡提示設計框架，將提示工程精煉為五個直觀元件：Character（角色）、Cause（原因）、Constraint（約束）、Contingency（應變）、Calibration（校準）。該框架旨在平衡結構控制與創意自由度，同時實現極高的 token 效率。

## 核心元件

### 1. Character（角色）
定義 AI 的身份、專業知識、語氣風格和行為特徵。

```
你是一位擁有 15 年經驗的科技行業產品經理，擅長將複雜技術概念轉化為使用者友好的產品說明。
```

### 2. Cause（原因/目標）
明確任務的目的、預期成果以及為什麼要完成這個任務。

```
目標：為即將釋出的企業級 SaaS 產品撰寫產品說明文件，幫助潛在客戶理解產品價值和核心功能。
```

### 3. Constraint（約束）
設定邊界條件、資源限制、執行規則和排除項。

```
約束：
- 文件長度不超過 800 字
- 避免使用技術術語，使用通俗語言
- 包含至少一個客戶成功案例
- 不要提及競爭對手
```

### 4. Contingency（應變）
定義備用方案、錯誤處理機制和安全回退策略。

```
如果無法獲取足夠的產品資訊，請：
1. 列出需要補充的關鍵資訊點
2. 提供一個通用的模板框架
3. 說明完成文件所需的後續步驟
```

### 5. Calibration（校準）
輸出最佳化指令，包括品質標準、驗證步驟和迭代要求。

```
校準：
- 完成後自檢：文件是否回答了"這是什麼"、"為什麼需要"、"如何使用"三個核心問題
- 確保每個功能點都對應一個具體的使用者收益
- 使用積極的、以結果為導向的語言
```

## 框架優勢

### Token 效率
5C 框架的核心優勢在於極高的輸入 token 效率：

| 提示風格 | 平均輸入 Token | 相對效率 |
|----------|---------------|----------|
| **5C** | 54.75 | 基準 |
| DSL | 348.75 | 6.4x 更多 |
| 非結構化 | 346.25 | 6.3x 更多 |

### 跨模型表現
在 OpenAI、Anthropic、DeepSeek、Gemini 四大模型家族測試中，5C 框架均表現出色：
- **Gemini 效果最顯著**：5C 僅需 54 tokens，而 DSL 需要 1,212 tokens
- **輸出品質**：在保持創意豐富度的同時，一致性優於非結構化提示
- **創意自由度**：相比 DSL 的剛性結構，提供更多語義探索空間

## 與傳統 DSL 對比

| 維度 | 5C Framework | DSL |
|------|--------------|-----|
| **學習曲線** | 平緩，直觀易懂 | 陡峭，需學習標記語法 |
| **Token 開銷** | 極低 | 高 |
| **認知負載** | 低，聚焦核心要素 | 高，需處理多層巢狀 |
| **創意自由度** | 高，LLM 保留"熵預算" | 受限，語法合規消耗創意 |
| **可移植性** | 跨模型、跨平臺 | 依賴特定 DSL 實現 |
| **結構化程度** | 中等，平衡靈活與規範 | 高，嚴格的標記語言 |

## 適用場景

### 推薦使用
- Token 敏感的應用（高頻 API 呼叫）
- 需要平衡結構與創意的任務
- AI 工程資源有限的個人/中小企業
- 快速原型設計和迭代
- 多模型部署（需要跨模型一致性）

### 可能不適用
- 需要嚴格 schema 驗證的場景
- 企業級 templates 標準化需求
- 複雜的多步驟工作流編排

## 實踐建議

1. **從 Character 開始**：明確定義角色是其他元件的基礎
2. **Constraint 要具體**：模糊的限制會產生模糊的輸出
3. **Contingency 不要省略**：定義回退策略提升可靠性
4. **Calibration 用於品質控制**：把它當作內建的質檢步驟
5. **保持簡潔**：5C 的優勢在於極簡，避免過度擴充套件

## 知識衝突

### 5C vs 複雜 DSL 之爭

**5C 立場**（Ugur Ari）：
- 複雜 DSL 的 token 和認知開銷限制了 LLM 的"熵預算"
- 簡化結構讓 LLM 專注於語義理解和創意生成
- 特別適合資源受限的場景

**複雜 DSL 立場**（部分企業實踐）：
- 嚴格的標記語言提供更好的可預測性和可驗證性
- 適合需要精確輸出格式的生產環境
- 便於程式化處理和解析

**調和觀點**：
兩種方式各有適用場景。5C 適合創意任務和資源敏感場景，複雜 DSL 適合結構化輸出和嚴格驗證場景。實際應用中可以根據任務型別選擇或組合使用。
